# 직원 스캔 쿠폰

- 고객은 내 쿠폰함에서 **직원에게 보여주기**를 누른다. 선택한 쿠폰의 60초 일회용 QR을 표시하고 자동 갱신한다. QR을 표시하거나 스캔하는 것만으로는 사용되지 않는다.
- 직원은 마이페이지 또는 쇼룸 관리의 **직원 쿠폰 스캔**을 연다. 처리 권한이 있는 매장을 선택하고 고객 QR을 스캔한다.
- 서버가 매장 권한·쿠폰 사용처·유효기간을 검증한 뒤 혜택과 주문 조건을 표시한다. 직원이 **할인 적용 완료**를 눌러 사용을 확정한다. POS에는 직원이 직접 혜택을 반영한다.
- 직원 화면은 응답 직후 완료로 바뀌고 고객 QR 화면은 2초 간격 조회로 같은 사용 번호·매장·혜택을 표시한다. 두 기기 모두 인터넷 연결이 필요하다. 고객 화면이 닫혀 있으면 쿠폰함 사용 내역에서 결과를 확인한다.
- `SINGLE`: 지정 매장 한 곳. `GROUP`: 지정 매장 목록. `ALL`: 전국 공용 참여에 동의한 활성 매장. 고객의 단골 가입 여부와 무관하다.
- 쇼룸 소유자는 바로 처리 가능하다. 직원은 바리스타 계정이 마이페이지 **매장 직원 신청**에서 해당 매장에 가입을 요청하고, 쇼룸 소유자가 쇼룸 관리 **직원 관리**에서 승인한 활성 바리스타 계정만 처리할 수 있다(전화번호 직접 등록 API는 `410`으로 종료). 프로필의 근무지 등록만으로 권한이 생기지 않는다. 소유자 변경·직원 권한 해제 후 접근은 차단된다. 본인 쿠폰은 다른 직원이 처리한다.
- 기존 고정 매장 QR 발급·검증, 고객 직접 사용 및 사용 요청 API는 `410`으로 종료한다. 이전에 열린 승인 요청의 처리와 기존 쿠폰 사용처 정책은 유지한다.

## 데이터와 운영

### 커스텀 쿠폰 정책 v2

- 금액 할인·정률 할인·상품 제공, 최소 주문액·최대 할인액·한국 시간 시작/종료·총 수량·고객당 1~10장·중복 할인·안내 조건을 설정하고 미리보기 후 등록한다.
- 타 매장을 지정하면 해당 점주의 참여 승인이 모두 필요하다. 전국 공용은 운영자 승인과 사용 매장의 전국 공용 참여 동의가 필요하다. 기존 정책 v1 쿠폰에는 이 동의를 소급하지 않는다.
- 비용 부담 주체는 발행 매장 또는 사용 매장으로 명시한다. 전국 공용은 발행 매장이 부담한다. 승인 이력에 결정자·시각을 저장한다.
- 발급된 쿠폰은 `couponSnapshot`으로 당시 조건을 보존한다. 등록 후 조건 변경·삭제 대신 추가 발급을 중단한다. 이미 받은 쿠폰은 원래 유효기간까지 사용 가능하다.
- 발급 요청 번호로 재시도를 중복 처리하지 않는다. 트랜잭션이 총 수량과 고객 한도를 함께 보장한다.
- 발급 API는 `{userId,couponId,claimRequestId}` 고유 인덱스를 먼저 만든 뒤 기존 `{userId,couponId}` 고유 인덱스를 교체한다. 요청 번호가 없는 기존 쿠폰은 고객당 한 장 제약을 유지한다. 구버전 서버를 함께 운영하는 배포는 피한다.

### 타임세일 알림

문구·대상(단골/최근 위치 공유 고객/둘 다)을 편집하고 대상 수를 조회한 뒤 발송한다. 마케팅 수신 동의, 한국 시간 21~08시 야간 동의, 주변 대상의 위치 공유 동의·최근 24시간·3km를 적용한다. 고객 전체 캠페인 기준 24시간에 한 번, 쿠폰 기준 1시간 간격이다. 발송 직전 동의와 계정 상태를 다시 확인한다.

전송 접수·실패·제외 수를 구분한다. 15분 이후 최근 결과 조회 시 Expo 영수증으로 APNs/FCM 전달 상태를 확인한다. 기기 표시·열람을 보장하지 않는다. 전송 접수 실패 시 고객 빈도 예약을 해제한다. 푸시는 현재 요청에서 20명씩 처리하므로 대규모 발송·프로세스 종료 후 자동 재시도에는 작업 큐가 필요하다.

기존 `barista_showrooms`가 매장이다. `coupons`는 허용 매장 정책, `user_coupons`는 고객별 상태다. `coupon_store_staff`는 매장·직원·권한 부여 소유자·활성 상태다. `coupon_presentations`는 쿠폰별 현재 QR의 SHA-256 해시·소유자·만료 시각·OPEN/USED/CANCELLED 상태를 저장한다. 원문 토큰과 개인정보를 QR URL이나 로그에 저장하지 않는다. QR은 URL 대신 전용 접두어와 난수 토큰만 포함한다. 표시 종료 시 미사용 토큰을 취소하며, 갱신하면 이전 QR은 무효다. 세션 문서는 24시간 후 TTL 정리하고 영구 사용 내역은 원장에 보존한다.

사용 시 `user_coupons`에 `usedAtStoreId`, `usedAtStoreName`, `usedAt`, `usageLogId`를 기록한다. `coupon_usage_logs`에는 발행 매장과 실제 사용 매장을 분리해 저장한다. 정산 참고 원장이며 결제·송금 기능은 없다.

MongoDB replica set 또는 Atlas가 필요하다. 직원 권한·사용처를 확정 때 재검증하며 쿠폰 차감·QR 소비·원장 저장은 동일 트랜잭션이다. 사용 번호를 원장 `_id`로 사용해 중복 저장을 방지한다. 같은 QR·직원·매장의 재시도만 기존 결과를 반환한다. 원장에 `method=STAFF_QR`과 `processedBy`를 기록한다. 푸시는 커밋 후 최선형 전달이며 사용 성공 조건이 아니다.

QR 사진만으로 고객이 직접 사용을 확정할 수 없다. 허가받은 매장 직원의 스캔·확인이 필요하다. 유효 시간 내 사진 전달이나 직원 공모까지 차단하는 방문 증명 수단은 아니다.

카메라는 HTTPS와 사용자 권한이 필요하다(localhost 제외). 카메라를 사용할 수 없으면 QR 사진 선택을 지원한다. 배포 전 iOS·Android 실기기 WebView의 카메라 권한, 인식, 백그라운드 복귀 및 QR 표시·양쪽 사용 완료를 확인해야 한다.

## 검증

```sh
pnpm --filter @blending/web test
pnpm --filter @blending/web typecheck
# 독립된 로컬 MongoDB replica set 전용. 운영 URI 사용 금지.
COUPON_TEST_MONGODB_URI='mongodb://127.0.0.1:27017/?replicaSet=test' pnpm --filter @blending/web exec tsx --test src/infrastructure/server/couponRedemptionRepository.test.ts src/infrastructure/server/couponPresentationRepository.test.ts
COUPON_TEST_MONGODB_URI='mongodb://127.0.0.1:27017/?replicaSet=test' pnpm --filter @blending/web exec tsx --test src/infrastructure/server/couponCampaignRepository.test.ts src/infrastructure/server/timesalePush.test.ts
```

트랜잭션 검증은 고유한 테스트 DB를 생성·삭제한다. 동시 요청, 타인 쿠폰, 위조 QR, 허용 매장, 만료, 비활성 매장, 원장 실패 롤백을 확인한다.
